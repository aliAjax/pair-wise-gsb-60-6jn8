# 医疗器械上市后安全信号核查与处置平台

面向医疗器械上市后安全团队的本地工作台，用于合并投诉、维修、不良事件和现场报告，维护证据矩阵、调查任务、风险状态、结论版本和审计轨迹。

## 技术栈

- SvelteKit 2 + Vite + TypeScript
- Skeleton UI + Tailwind CSS
- Svelte stores
- SvelteKit Form Actions
- TanStack Query for Svelte
- Zod

## 主要工作区

- `/`：开放信号、高风险信号、任务和逾期总览
- `/signals`：关键词与多条件筛选、人工登记新信号
- `/signals/[id]`：证据矩阵、状态流转、补充证据、结论版本、重新打开和审计
- `/trends`：发生率趋势与阈值核对
- `/batches`：批号覆盖与报告追踪
- `/audit`：跨信号审计时间线和 JSON 报告导出

## 证据—结论—批次—任务联动规则

- 新证据登记为**相反证据**（可勾选推翻的结论版本，默认指向全部当前有效版本），或对已有证据做**强度标记变化**后，引用过该证据的结论版本立即失效、进入**待复核**；原版本记录与原证据均保留，只追加失效状态，不删除、不回写。
- 结论失效后信号回到「复核中」，关联批次**不再按已处置统计**（批次已处置口径 = 关联信号全部已关闭且结论持续有效）。
- 原调查任务保留，已关闭（done）的任务自动转为「已暂停关闭（待复核）」，复核前不计逾期。
- 证据登记、结论失效、批次口径、任务暂停在**同一个原子事件**内生效。

## 持久化与一致性

- 采用**写前操作日志（write-ahead journal）+ 状态快照**：修改先追加事件落盘，再更新内存与快照；写入中断后重开自动重放日志恢复，已确认结论和原证据不丢。
- 证据表单提交前会把内容存为「未完成核对」草稿；服务端校验失败或本地写入失败后，重开信号页可一键恢复继续提交，成功后自动清除。
- 两个窗口同时保存证据时，事件带全局唯一 ID，通过 `storage` 事件按事件 ID 并集合并，两份记录都会留下。
- 旧版本数据（v1，缺少结论—证据关联）首次加载时执行三阶段迁移：先迁移原结论 → 补齐证据关联 → 再对引用相反证据的结论补做失效；历史审计只追加不回写。
